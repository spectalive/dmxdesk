# Qt Quick Desk Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a fully functional Qt Quick desk on the TAQ-102 for comparison with the established C interface.

**Architecture:** The C desk runtime continues to own QLC+ and safety semantics in an optional headless child process. Standard pipes exchange touch events and validated view snapshots with a separate Qt Quick process that owns the visual surface.

**Tech Stack:** C99, Qt 6.9.1 C++ and QML, Buildroot, EGLFS, standard pipes.

**Spec:** `docs/superpowers/specs/2026-10-21-qt-desk-design.md`

## Global Constraints

- Keep the C desk as the boot default until full parity and a physical comparison are verified.
- Never expose credentials in view snapshots or repository artifacts.
- Reuse existing QLC+, hold, speed, model and setup logic for all actions.
- Use English for source and documentation; operator labels follow the show's Spanish map.
- Each new source file has one primary responsibility.

## Review Focus

- Qt disconnects during a held Flash or fog press: the backend must release it.
- A reconnect occurs after a toggle press: the action must not be replayed.
- The loaded master serves a different show: all show controls must be inert.
- A second finger reaches stop-all while another gesture is captured.
- A settings snapshot contains a Wi-Fi password: serialization must exclude it.

---

### Task 1: Headless transport

**Files:** Create focused pipe parsing files under `src/` and a host test; modify `src/dmxdesk.c` and `src/dmxdesk.sources`.

**Interfaces:** Accept `--qt-pipe`; read bounded touch lines from standard input and publish JSON snapshots on standard output. EOF cancels every capture. Normal C desk mode is unchanged.

- [ ] Test framed input, malformed messages, EOF and bounded output.
- [ ] Add headless startup without DRM or evdev touch, using 1024x600 layout coordinates.
- [ ] Feed Qt events through the existing gesture loop; cancel captures and release holds on disconnect.
- [ ] Run the C host suite and an ASan mock-master disconnect test.

### Task 2: Validated view snapshots

**Files:** Create `src/desk_view_snapshot.h`, `src/desk_view_snapshot.c`, and tests.

**Interfaces:** Serialize the current `desk_model`, `desk_speed`, and safe `desk_setup` fields to one bounded JSON line on state change. Include page, bank, placement geometry, control kind, enabled, state, pending, label, icon, swatches and tempo. Exclude passwords and network secrets.

- [ ] Test enabled and disabled controls, mismatch, colour mode, speed echoes, haze exclusivity and secret exclusion.
- [ ] Emit snapshots after model changes; enforce a maximum message size.
- [ ] Compare snapshot controls with the same C model used by the painter.

### Task 3: Qt transport and state model

**Files:** Create focused C++ bridge files under `qt/` and Qt tests; add `qt/CMakeLists.txt`.

**Interfaces:** A `QObject` bridge launches the C backend via `QProcess`, exposes the validated snapshot to QML, and sends touch down, move, up and cancel. A backend exit cancels every local touch and shows connection state.

- [ ] Test framing, reconnect, stale state, touch IDs and cancellation with a local fake backend.
- [ ] Build and run the host Qt application against recorded snapshots.

### Task 4: Full Qt surface

**Files:** Add one QML component per page or single-responsibility visual unit under `qt/qml/`, plus generated icon assets from the desk's existing vector source.

**Interfaces:** Render only snapshot data and send gestures through the bridge. Cover DIRECTO, EFECTOS, RITMO, settings, lock, colours, smoke, fader, stop-all and status.

- [ ] Capture all pages and disabled, waiting, mismatch, hold and selected states at 1024x600.
- [ ] Compare labels, touch geometry and icons with C desk frames.
- [ ] Test touch targets, fader drag, one-shot colours and speed fine steps using a fake backend.

### Task 5: Tablet trial and recovery

**Files:** Add a trial-only Buildroot configuration or build script in `taq102`; update documentation and the test backlog.

**Interfaces:** Build Qt in an isolated output, install the trial under `/data`, launch it without replacing the C boot image, and restore C automatically on failure.

- [ ] Verify package and image contents, Qt plugins, fonts and touch mapping.
- [ ] Run mock-master interaction on the tablet, then controlled live QLC+ parity checks.
- [ ] Verify the C desk returns and is linked after the trial; record performance and the owner's comparison.
